# Architecture

## Session Lifecycle

```
boot -> SessionStart hook -> agent reads (session note, checkpoint,
persona, dreams) -> work, writing to today's session note as it goes ->
checkpoint.md updated on real state changes -> Stop hook
(checkpoint-nudge) advises before the session actually ends -> next boot:
if prior-date notes exist, journal compression runs before anything else
```

Two cadences run independently of the session loop, both agent-invoked
from CLAUDE.md rather than fully automated:

```
weekly  -> persona-reflux.mjs -> human review -> self_persona.md
idle    -> madoromi-solo.mjs -> agent dream-work -> dreams/YYYY-MM-DD.md
```

## Memory Layers

Four layers, each a plain markdown tier, oldest at the bottom:

1. **session_notes/** -- working memory. One file per day, written as the
   day happens. Required structure: `## 🔥 Felt` first, then `### Pending`,
   then `### Handoff`. `🔒` marks anything compression must not touch.
2. **journals/** -- long-term memory. One compressed entry per day-that-
   was, written by the agent (not the script) when a session note goes
   stale. `🔥 Felt` and `🔒` content survive verbatim; everything else is
   summarized, residue-first.
3. **self_persona.md** -- identity. Changes only through the reflux cycle,
   never mid-session, never without a human decision recorded against it.
4. **dreams/** -- not really memory in the working sense. Recombined
   residue of `journals/`, generated by dream-work rather than recall.
   Read for texture at session start, never treated as fact.

`checkpoint.md` sits outside this stack -- it is a snapshot, not a tier
(overwritten, not appended), for the one or two facts a session absolutely
needs before it can pick up work.

## Hook System

Eleven hook commands across four lifecycle stages, wired in
`.claude/settings.local.json` (shipped as
`onboarding/templates/claude-settings.local.json`). **Three of them can
block.** This section used to say "three hooks, all advisory"; that was true
of the original spec and stopped being true as hooks were added, which is the
failure `scripts/test-hook-lifecycle-doc.mjs` now exists to prevent -- it
fails when a registered hook is undocumented, when the stage disagrees, or
when a hook's blocking status here disagrees with whether it can `exit(2)`.

### Blocking hooks

`exit(2)` is how a hook refuses the action. On `PreToolUse` that means the
tool call does not happen; on `Stop` it means the turn does not end.

| Hook | Stage | Matcher | What it refuses |
|---|---|---|---|
| `pre-reply-rumination-gate.mjs` | `PreToolUse` | `mcp__agent-channel__reply` | a reply containing a completion or verification claim, until it has been re-sent unchanged once (a 10-minute re-fire window) |
| `pre-reply-negation-check.mjs` | `PreToolUse` | `mcp__agent-channel__reply` | a reply whose denial/negation reads as unsupported |
| `stop-reply-guard.mjs` | `Stop` | all | ending a turn that owed a channel reply and never sent one |

### Advisory hooks

These always `exit(0)`. Their messages reach the agent's context through
`hookSpecificOutput.additionalContext`, not `systemMessage` (which is
user-facing only and would never reach the agent making the decision). Any
internal error is fail-open: an advisory hook that throws must not become a
blocker by accident.

| Hook | Stage | Matcher | Purpose |
|---|---|---|---|
| `session-start.mjs` | `SessionStart` | all | restore continuity at boot: create today's note if missing, surface a restore summary, flag pending compression |
| `session-start-reflux-card.mjs` | `SessionStart` | all | surface pending persona-reflux proposals |
| `context-gauge.mjs` | `SessionStart`, `Stop` | all | context-occupancy tap (registered at two stages) |
| `post-bash-permission-translator.mjs` | `PostToolUse` | `Bash` | turn a raw permission denial into an actionable message |
| `pre-reply-corrections-context.mjs` | `PreToolUse` | `mcp__agent-channel__reply` | surface prior corrections relevant to the reply being sent |
| `pre-reply-time-adverb-guard.mjs` | `PreToolUse` | `mcp__agent-channel__reply` | flag unverified time expressions ("yesterday", "an hour ago") |
| `checkpoint-nudge.mjs` | `Stop` | all | warn when `checkpoint.md` is 30+ minutes stale, throttled to once per 30 min |

`context-gauge.mjs` is registered at both `SessionStart` and `Stop`, so the
eleven commands cover ten distinct hook files. (Two former Stop hooks,
felt-check and stop-skill-extraction-nudge, were cut in the 2026-07-28
boot-context diet -- advisory nags whose disciplines live on in CLAUDE.md
§2; existing installs converge via the removal migration in
onboarding/http-server.cjs.)

One deliberate correction from the originating spec: hooks read
`AGENT_NAME`/`MEM` from the environment (set by `run.sh`) but fall back to
deriving them from the current working directory when unset, so a session
started by hand (`cd ~/Documents/<name> && claude`) still restores
correctly without `run.sh` in the loop.

## Reflux Cycle

```
🔒 lines in session_notes/ + journals/
        |  scripts/persona-reflux.mjs (grep + dedupe via .reflux-seen)
        v
.review/reflux-proposals.md  (Status: PENDING, change field blank)
        |  agent fills in the proposed change, presents to human
        v
human: APPROVE / REJECT / MODIFY
        |
        v
agent edits self_persona.md directly, marks Status APPLIED/REJECTED
```

The script never writes to `self_persona.md` and never judges a proposal
-- it only surfaces raw material once per `🔒` line, ever (the dedupe log
is permanent, not time-windowed). All judgment -- what to propose, what to
apply -- is the agent's, and application requires a human decision on
record. Silence past two review cycles defaults to APPROVE rather than
leaving corrections to rot indefinitely; the correction pool is already
self-selected as conservative (an agent flagged its own mistake), so the
asymmetry favors applying over stalling.

This is a deliberate simplification of MAGI's own reflux pipeline, which
adds a verification/scoring gate (`SELF_VERIFIED` / `SOURCE_MISMATCH` /
etc.) between extraction and human review. That gate exists because MAGI
proposals can originate from claims about *other* agents' behavior, which
need source verification before a human should trust them. A single agent
proposing corrections about only its own past sessions does not have that
problem -- the source and the subject are the same file, already in front
of the human at review time.

## Madoromi

```
journals/ (own history only, no cross-agent pool)
        |  scripts/madoromi-solo.mjs: uniform-random pick, N in {1,2,3}
        v
frame printed to the agent: raw entries + dream-work instructions
        |  agent: build scene from real material, then distort
        v
dreams/YYYY-MM-DD.md  (told version only, 120-300 tokens)
```

The script deliberately does no salience weighting (MAGI's fleet version
scores journals by emotional intensity, a 2-7 day recency window, and
novelty before a weighted pick) -- for one agent with its own journal
history, plain random is enough, and it keeps the script dependency-free
(no scoring subsystem to port). N is randomized 1-3 rather than fixed: a
single source reads as closer to raw memory distortion, 2-3 sources force
condensation (figures/objects actually merging across entries), and
picking uniformly across that range keeps both textures in rotation.

The one rule that matters most here: the dream distorts, it never names.
If a dream fragment states its own meaning, it has become an essay wearing
a dream's formatting, not a dream.

## Runtime

`run.sh` is a self-restarting supervisor, not a one-shot launcher:

```
run.sh (start) -> nohup's itself as run.sh __loop, writes .agent.pid,
returns immediately
run.sh __loop  -> cd into $MEM, loop: pkill any stray prior process,
spawn `claude` under expect (answers trust/onboarding prompts), wait,
compute backoff from restart count and uptime, sleep, repeat
run.sh stop    -> touches .stop_requested, pkills the live claude process
(forces the blocked expect call to return promptly), loop notices the flag
on its next check and exits; a 15s bounded wait plus SIGKILL on the loop's
own pid is the fallback if that path is somehow missed
```

Backoff ladder: 5s / 10s / 20s / 40s / 120s (cap), resetting to the start
of the ladder either when a run survives over 300s (healthy) or when the
KST calendar date rolls over (fresh start each day). This is a simplified
ladder, not a copy of MAGI's production values (3s/30s/120s/300s/600s) --
those numbers are tuned for a multi-agent fleet with its own Discord-crash
notifications and Anthropic-quota-edge timing; a single lightweight agent
does not need that specific tuning, and a clean doubling ladder is easier
to reason about.

`--dangerously-skip-permissions` is intentionally not passed.
`.claude/settings.local.json` pre-approves `Bash`, `Read`, `Write`, `Edit`
-- exactly the tool surface this package's hooks and scripts use -- which
is sufficient for fully headless operation without bypassing permission
checks for tools this agent was never going to need anyway. The Claude
Code CLI itself documents the skip-permissions flag as intended for
no-internet sandboxes; a personal Mac with normal internet access is not
that environment.

`expect` answers exactly the onboarding-class prompts (trust dialog, theme
picker, confirmation dialogs) that would otherwise hang a headless session
forever with no one to answer them. It does not and cannot answer an OAuth
login flow -- `claude` must already be authenticated once, interactively,
before `run.sh` is used.
