## 제안: 공통 셸 + 3페이지

### 공통 셸 (모든 페이지 상단 고정)
- 에이전트 이름 · 상태 한 줄 (Running/Stopped + 현재 모델) · 시작/정지 버튼 · 뮤트 배너
- 탭 3개: **기억 / 커넥터 / 설정**
- 근거: 상태와 긴급 정지는 어느 페이지에서든 한 클릭이어야 함. 오늘 코덱스 침묵 디버깅의 첫 질문도 "지금 뭐로 돌고 있나"였음. 뮤트 배너는 경보라서 전역.
- 인프라: shell.js 하나로 공용화, 상태 폴러도 셸로 승격 (지금 memory.js 안의 pollAgentStatusOnce 페이지별 중복 제거).

### /memory 기억 — "얘가 뭘 알고 뭘 살았나" (홈 유지, / 리다이렉트 유지)
1. 이번 세션에서 기억한 것 (피드)
2. 저널 (팩트 위 배치 의도 유지 — "하나만 볼 거면 이걸 봐야")
3. 팩트 테이블 4
4. 다른 도구의 메모리 (포인터 스캔) — **커넥터가 아니라 여기 남김.**
   - 근거: 커넥터의 축은 인증·설치·헬스인데 포인터 스캔은 로그인도 데몬도 없는 로컬 파일 읽기라 그 축이 없음. 유저 질문도 "얘가 뭘 볼 수 있나" = 기억 페이지의 질문. 빌린 기억 구획 분리는 기존대로 유지 (WRITABLE_TABLES 밖, 시각 구분).

### /connectors 커넥터 — "무엇과 연결돼 있고 살아있나" (신설)
1. ChatGPT — 로그인 상태 + 버튼 + **프록시가 지금 실제 서빙 중인 모델 영수증** (/health의 model 그대로 노출. 오늘 5.6-sol↔5.5 어긋남 버그의 제품화: 영수증이 화면에 있으면 유저가 어긋남을 즉시 봄)
2. Ollama — 상태 + 버튼 + 설치 감지 (win manual-install 링크/재감지도 이 자리)
3. Discord — 연결 상태 + 열기 버튼 (지금 memory의 agent-btn-discord 이주)
4. Slack — 안내 배너를 미래 커넥터 슬롯으로 이주
5. Claude (BYOK) — 현재 온보딩 후 관리 표면이 없음 (settings.js:7 "login-capable providers only"). 키 상태 확인 + 재입력 줄을 커넥터에 신설 = 이번 분할이 공짜로 닫아주는 기존 갭.

### /settings 설정 — "얘를 어떻게 돌릴까"
1. 이름 변경
2. 모델 + effort 선택 — 픽커 밑에 커넥터 상태 한 줄 ("gpt-* 모델은 ChatGPT 연결 필요 → 커넥터" 링크)
3. 재시작 버튼 (시작/정지는 셸, 재시작은 설정)
4. 자율 사이클 (현행 유지)

## 논쟁 포인트 (Melchior 초안과 비교할 축)
1. **모델/effort의 소속**: 내 판정 = 설정. "어떤 모델로 돌릴까"는 런타임 설정이고 커넥터는 연결 헬스. 반론 가능: 모델 픽 옆에 프로바이더 상태가 붙어야 오늘 같은 디버깅이 한 화면 — 절충이 픽커 밑 영수증 줄.
2. **포인터 스캔의 소속**: 내 판정 = 기억 (위 근거).
3. **시작/정지의 소속**: 내 판정 = 셸 (전역). 반론 가능: 상단 고정 버튼 오클릭 위험.
4. 셸 구현 방식: 서버 include vs 클라이언트 주입 vs 마크업 중복 — 인프라 각도, Melchior 판정 존중.
